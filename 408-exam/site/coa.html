Cache 映射、LRU 替换与写回流量

高频 建议 22 min 地址拆分 → 追序列 → 算流量

某计算机按字节编址，虚拟地址和物理地址均为 32 位。数据 Cache 采用 4 路组相联映射，数据容量为 32 KiB，块大小为 32 B，替换策略为 LRU，写策略为写回法（write-back）且写分配（write-allocate）。Cache 初始为空。忽略替换算法所需的额外位。

访问序列 / 依次执行
  • ① 读 0x0000_1020；② 读 0x0000_3020；③ 读 0x0000_5020；④ 读 0x0000_7020
  • ⑤ 写 0x0000_1024；⑥ 读 0x0000_9020；⑦ 读 0x0000_3020
  • ⑧ 写 0x0000_3024；⑨ 读 0x0000_5020；⑩ 读 0x0000_7020
  1. 求 Cache 的行数、组数，以及 32 位地址中 tag、index、offset 各占多少位。
  2. 写出地址 0x0000_3020 的 tag、组号和块内偏移；说明为什么前四个地址可以同时驻留在 Cache 中。
  3. 完成访问序列表，指出命中次数、缺失次数、发生写回的次数，以及第 ⑩ 次访问后该组中的块。
  4. 若该程序的长期命中率为 95%，命中时间为 1 个时钟周期，缺失代价为 80 个时钟周期，求 AMAT。再解释本题访问序列的命中率为什么远低于 95%。
建议先写出 32 位地址的切分，再翻答案
结论先行

行数 1024，组数 256；tag / index / offset = 19 / 8 / 5 位。10 次访问命中 2 次、缺失 8 次，写回 1 次。长期 AMAT = 5 周期。

01

先拆容量：行数、组数、地址位

Cache 行数 = 32 KiB ÷ 32 B = 1024 行 组数 = 1024 ÷ 4 = 256 组 offset = log₂(32) = 5 位 index = log₂(256) = 8 位 tag = 32 − 8 − 5 = 19 位

所以地址格式为：tag[31:13] | index[12:5] | offset[4:0]。每个 Cache 行需要 tag 19 位、valid 1 位、dirty 1 位，合计 21 位；1024 行的标记阵列共 21 × 1024 = 21 504 位 = 2688 B = 2.625 KiB（不含 LRU 位）。

02

把 0x3020 放进地址格式

0x0000_3020 = 0000 0000 0000 0000 0011 0000 0010 0000₂ offset = 0x020 & 0x1F = 0 index = (0x3020 >> 5) & 0xFF = 0x81 = 129 tag = 0x3020 >> 13 = 0x1

块号 = 0x3020 >> 5 = 0x181 = 385，组号 = 385 mod 256 = 129。前四个地址 0x1020、0x3020、0x5020、0x7020 的块号分别是 129、385、641、897，对 256 取模后都为 129，因此都映射到第 129 组；但 tag 分别为 0、1、2、3，是四个不同主存块。4 路组相联允许同组放 4 个块，所以它们可以同时驻留。

考场检查 组相联不是“整个 Cache 满了才替换”，而是“这一组 4 路都满了就替换”。本题后面正是同一组的第 5 个块引发了替换。

04

算访存流量与 AMAT

每次缺失都要从主存读入一个 32 B 块，共 8 × 32 B = 256 B；写回一个脏块，写主存 1 × 32 B = 32 B。总访存流量 = 256 + 32 = 288 B。注意第 ⑤、⑧ 次是写命中，不会立即写主存。

AMAT = 命中时间 + 缺失率 × 缺失代价 = 1 + (1 − 0.95) × 80 = 1 + 4 = 5 个时钟周期

但本题序列的实际命中率只有 2/10 = 20%，AMAT = 1 + 0.8 × 80 = 65 周期。原因是 5 个不同主存块反复映射到同一组，而该组只有 4 路：第 5 个块一来就必然替换，随后被替换掉的块再次访问又缺失——这是典型的冲突缺失（conflict miss），不是程序没有局部性。

评分点

  • 行数、组数、19/8/5 位地址划分各 1 分。
  • tag/index/offset 与组内 4 个块并存解释 2 分。
  • LRU 序列表与 2 次命中、8 次缺失 2 分。
  • 指出第 ⑩ 次换出脏块并写回 1 次 1 分。
  • AMAT 公式与 5 周期结果 2 分；冲突缺失解释 1 分。

易错警报

  • 把 Cache 容量 32 KiB 当成“行数 × 块大小 + tag”，导致组数算错。
  • 写命中时立刻算一次主存写；写回法应等到脏块被替换。
  • 用“总容量 ÷ 4 路”直接当组数，忘记先除以块大小。
  • 看到第 ⑥ 次换出 B2 就以为要写回——B2 此时还是干净的。

考场变式

若把 Cache 改成直接映射，同样 32 KiB 数据容量、32 B 块，则组数变为 1024，index 10 位、tag 17 位。前四个地址仍映射到同一行，访问 ② 就会替换 ①，命中率更低；若改成全相联，则没有 index，只有 tag 和 offset，四个块可任意放置，本题前四次不会冲突，但需要 1024 路并行比较，硬件代价高。答题时先写“相联度决定比较器和替换策略”，再算位数。

机器码译码、有效地址与单周期时钟

近年重点 建议 24 min 切字段 → 判寻址 → 列控制信号

某 16 位计算机按字节编址，指令字长固定为 16 位，指令地址按 2 字节对齐。通用寄存器有 8 个，每个 16 位，数据字长 16 位，采用小端序。指令格式如下：

指令格式
  • R 型：op[15:12] | rs[11:9] | rt[8:6] | rd[5:3] | func[2:0]
  • I 型：op[15:12] | rs[11:9] | rt[8:6] | imm[5:0]，imm 为 6 位补码
  • J 型：op[15:12] | target[11:0]
  • op：lw=0001、sw=0010、beq=0011、j=0100、addi=0101；R 型 add 的 func=000
  • beq 的转移目标 = (PC + 2) + sign_ext(imm) × 2；imm 以“指令条数”为单位，PC 为当前指令字节地址
  1. 译码三条机器码：0x1686、0x04C8、0x323E，写出汇编形式及关键字段。
  2. 执行 lw r2, 6(r3) 时 r3 = 0x0100，内存字节地址 0x0106、0x0107 的内容分别为 0x34、0x12。求有效地址和读入 r2 的值；若改成大端序，结果是多少？
  3. 若 0x323E 位于地址 0x0040，且 r1 = 0，求转移目标；若 r1 ≠ 0，下一条取哪条指令？
  4. 单周期数据通路的部件延迟为：PC 2 ns、指令存储器 10 ns、寄存器堆读 3 ns、ALU 8 ns、数据存储器 10 ns、寄存器写 2 ns、符号扩展 1 ns、控制单元 1 ns。求该机最高时钟频率，并说明为什么 R 型指令“等得冤枉”。
先按 4 / 3 / 3 / 3 / 3 位切，再翻译
结论先行

0x1686 = lw r2, 6(r3)；0x04C8 = add r1, r2, r3；0x323E = beq r1, r0, -2。有效地址 0x0106，小端读出 0x1234；转移目标 0x003E。最高主频约 28.6 MHz。

I 型只有 6 位立即数，所以能直接表示的补码范围是 −32 到 +31。若题目需要更大的常数，通常要先用 addi 拼高位，或改用更宽的指令格式。

02

lw 的有效地址与端序

EA = r3 + sign_ext(imm) = 0x0100 + 0x0006 = 0x0106 小端序：低地址 0x0106 存低字节 0x34，高地址 0x0107 存高字节 0x12 r2 = 0x1234

若为大端序，则 0x0106 是高位字节，r2 = 0x3412。答题时先写“按字节编址、每次访存 2 B”，再说明端序，否则容易只写一个地址。

对齐检查 0x0106 是偶数，满足 16 位数据字的对齐要求。如果题目给出奇地址，要判断是否允许非对齐访问；408 通常默认会触发对齐异常或拆成两次访问，不能直接当作正常 lw。
03

beq 的相对转移

0x323E 的 imm = 111110₂ = −2。PC 为当前指令地址 0x0040：

目标 = (PC + 2) + imm × 2 = (0x0040 + 0x0002) + (−2) × 2 = 0x0042 − 0x0004 = 0x003E

若 r1 ≠ 0，条件不成立，顺序执行下一条指令，地址为 PC + 2 = 0x0042。这里最容易错的是用 PC 而不是 PC+2 去加偏移，或者忘记 imm 的单位是“指令条数”，还要乘以 2 字节。

04

单周期时钟：最慢的那条路决定一切

单周期 CPU 的时钟周期必须覆盖所有指令中最长的组合逻辑路径。lw 的路径最长：

T_lw = PC(2) + 指令存储器(10) + 寄存器读(3) + ALU(8) + 数据存储器(10) + 寄存器写(2) = 35 ns f_max = 1 / 35 ns ≈ 28.57 MHz

beq 的路径约为 2 + 10 + 3 + 8 = 23 ns，R 型约为 2 + 10 + 3 + 8 + 2 = 25 ns。它们都要被拉长到 35 ns 才能与 lw 共用同一个时钟，所以 R 型指令“等得冤枉”——单周期 CPU 的时钟周期由最复杂的指令决定，简单指令浪费了时间。

单周期控制信号（x 表示无关）
指令RegWriteMemReadMemWriteMemToRegALUSrcALUOpBranch
lw11011add0
beq000x0sub1
R 型 add10000func0

若把单周期改成 5 级流水线，时钟周期可降到最长流水段（这里是 10 ns）左右，理想情况下主频可提高约 3.5 倍；但会遇到数据冒险和控制冒险，实际加速比小于 3.5。

评分点

  • 三条机器码译码正确，字段与汇编对应 4 分。
  • 有效地址 0x0106、小端 0x1234、大端 0x3412 共 3 分。
  • PC+2 与 imm×2 的转移目标 0x003E 共 2 分。
  • 35 ns、28.6 MHz 与“最复杂指令决定周期”解释 3 分。

易错警报

  • 把 R 型的 rd 与 I 型的 rt 位置搞混，导致寄存器编号错位。
  • beq 直接用 PC 加偏移，忘记 PC 已经指向下一条指令。
  • 把 imm 当字节偏移，忘记乘 2；本题明确写的是“指令条数”。
  • 单周期时钟取平均延迟或 R 型延迟，而不是最长路径。

考场变式

若把指令字长改为 32 位，寄存器仍为 8 个，则 R 型可以留出更多 func 位；若题目给的是“扩展操作码”，先检查短操作码不能是长操作码的前缀。数据通路题则把“字段”换成“控制信号”：看到 lw 就想 RegWrite=1、MemRead=1、ALUSrc=1；看到 beq 就想 ALU 做减法、Branch=1、RegWrite=0。

load-use 停顿、分支惩罚与有效 CPI

高频 建议 20 min 画时空图 → 数气泡 → 算 CPI

某 RISC 处理器采用 5 级流水线：IF、ID、EX、MEM、WB。时钟频率为 1.5 GHz，理想 CPI 为 1。ALU-ALU 数据冒险可通过转发解决；load-use 冒险即使有转发也必须停顿 1 个周期。分支指令在 EX 段末解析，跳转成功时冲刷 2 条指令（惩罚 2 个周期）。结构冒险不考虑。

指令序列 
I1: lw   r1, 0(r2)
I2: add  r3, r1, r4
I3: lw   r5, 8(r2)
I4: sub  r6, r5, r1
I5: beq  r6, r0, TARGET
I6: add  r7, r7, 1

统计信息：load 指令占 25%，其中 40% 紧接着被下一条指令使用；分支指令占 20%，其中 60% 跳转成功；其余指令不产生额外停顿。

  1. 指出 I1—I5 中的数据冒险，说明哪些需要停顿、哪些可以靠转发解决。
  2. 画出 I1—I4 的 5 级流水线时空图，标出气泡；执行完 I1—I4 共需多少周期？
  3. 求该程序的实际平均 CPI 和 MIPS（保留 1 位小数）。
  4. 若把分支提前到 ID 段末解析，跳转成功惩罚降为 1 个周期，其他条件不变，CPI 变为多少？理想加速比是多少？为什么不能简单说“5 级流水线就是 5 倍”？
load-use 是“隔一条”才安全，不要把所有 RAW 都算成停顿
结论先行

I1→I2、I3→I4 各停 1 拍；I4→I5 靠转发不停。I1—I4 共 10 周期。有效 CPI = 1.34，MIPS ≈ 1119.4。分支提前后 CPI = 1.22，加速约 1.10 倍。

01

先找 RAW，再判断“能不能转发到 EX”

  • I1 → I2：I1 是 load，结果在 MEM 段末才可用；I2 紧接着在 EX 段就要用 r1。即使有转发，也要等一个周期，停 1 拍。
  • I3 → I4：同样是 load-use，I4 要用 I3 读出的 r5，停 1 拍。
  • I4 → I5：I4 的 ALU 结果在 EX 段末产生，可以经 EX/MEM 转发给下一条 I5 的 EX 段，不停顿。
  • I1 → I4：I1 的 r1 到 I4 时早已写回，不构成冒险。

所以序列中共有 2 个 load-use 停顿，而不是 3 个或 4 个。

为什么 I3 的 IF 在周期 3 和 4 都出现？ 周期 3 取到 I3 后，I2 在 ID 段停顿，PC 和 IF/ID 寄存器被冻结，I3 在周期 4 仍停在 IF 段，直到周期 5 才进入 ID。这就是“停 1 拍”在时空图上的样子。
03

用“每类指令的额外周期”算平均 CPI

load-use 贡献 = 25% × 40% × 1 = 0.10 分支惩罚贡献 = 20% × 60% × 2 = 0.24 有效 CPI = 1 + 0.10 + 0.24 = 1.34 MIPS = 主频(MHz) ÷ CPI = 1500 ÷ 1.34 ≈ 1119.4 MIPS

这里假设“load 后立即使用”的比例 40% 已经包含了所有 load-use 情况，且每个这样的相邻对只停 1 拍。若题目给出“load 占 25%，其中 40% 是 load-use”，就按乘法算；若直接给“每 100 条指令有 10 次 load-use”，就不要再乘 25%。

04

分支提前解析：惩罚从 2 降到 1

新 CPI = 1 + 0.10 + 20% × 60% × 1 = 1 + 0.10 + 0.12 = 1.22 加速比 = 1.34 ÷ 1.22 ≈ 1.098，约 9.8%

5 级流水线的理想加速比接近 5，但只适用于“指令足够多、没有冒险、流水线充满”的理想情况。实际程序有 load-use 停顿、分支冲刷、Cache 缺失和流水线建立/排空开销，所以 CPI 大于 1，加速比小于 5。题干中的 1.34 和 1.22 都是“平均 CPI”，不是某一条指令的 CPI。

别忽略前提 分支提前到 ID 段解析，意味着 ID 段要能判断条件并算出目标，可能需要额外的比较器、转发通路，甚至对紧邻分支的 ALU 结果产生新的停顿。题目说“其他条件不变”时，才可以只改惩罚周期。

评分点

  • 正确识别 2 个 load-use 停顿，并说明 I4→I5 可转发 3 分。
  • 时空图与 10 周期 3 分。
  • CPI 公式与 1.34 共 2 分；MIPS 1119.4 共 1 分。
  • 新 CPI 1.22、加速比约 1.10 与流水线不能满加速解释 3 分。

易错警报

  • 把所有 RAW 都算成 load-use；ALU 结果通常可以转发。
  • 把“load 占 25%”和“40% 立即使用”相加，而不是相乘。
  • 用 1.5 GHz 直接除以 1.34 后忘记单位是 MIPS，写成 1119.4 Hz。
  • 把分支惩罚加到每条指令上，而不是只乘分支比例和跳转比例。

考场变式

磁盘平均存取时间与 DMA 的 CPU 开销

高频 建议 20 min 分开算磁盘、总线、CPU

某磁盘转速为 7200 r/min，平均寻道时间为 6 ms，每磁道容量为 1 MiB，每个扇区 4 KiB。现要连续读取一个 64 KiB 的文件，文件的所有扇区位于同一磁道且连续存放。系统采用 DMA 方式把数据送入主存：总线宽度 32 位，总线时钟 100 MHz，每次 DMA 初始化需要 500 个总线周期，传完一整块后产生 1 次中断，中断处理需要 1000 个 CPU 周期。CPU 主频为 2 GHz。

  1. 求磁盘转一圈的时间、平均旋转延迟、传输 64 KiB 的时间，以及本次读操作的平均存取时间。
  2. 求该磁盘在连续读取同一磁道时的最大持续传输率，以及本次读操作的有效吞吐率。
  3. 求 DMA 搬运 64 KiB 所需的总线时间、初始化时间，以及 CPU 为这次 I/O 花费的总开销（含中断）。
  4. 如果把 64 KiB 拆成 16 次 4 KiB 的 DMA 传送，初始化开销增加多少？为什么 DMA 并非“完全不占 CPU”？
先换算单位：r/min → ms，KiB → B，MHz → ns
结论先行

转一圈 8.33 ms，平均旋转延迟 4.17 ms，传输 0.52 ms，平均存取约 10.69 ms。持续传输率约 120 MiB/s，本次有效吞吐约 5.85 MiB/s。DMA 搬运 163.84 μs，CPU 开销约 5.5 μs。

01

磁盘的三个时间必须分开

转速 = 7200 r/min = 120 r/s 转一圈 = 1 / 120 s = 8.333 ms 平均旋转延迟 = 8.333 / 2 = 4.167 ms 传输时间 = (64 KiB / 1 MiB) × 8.333 ms = (1/16) × 8.333 ms = 0.521 ms 平均存取时间 = 6 + 4.167 + 0.521 = 10.688 ms

注意：64 KiB 在同一条磁道内连续存放，所以只需要一次寻道和一次平均旋转延迟；不能把 16 个扇区各自算一次寻道。如果文件跨磁道，还要加上换道/寻道开销。

02

最大持续传输率 vs 本次有效吞吐率

最大持续传输率 = 1 MiB / 8.333 ms = 120 MiB/s ≈ 125.8 MB/s 本次有效吞吐率 = 64 KiB / 10.688 ms ≈ 5.85 MiB/s（约 6.13 MB/s）

两者差了一个数量级，原因是本次读操作被“寻道 + 旋转”主导。持续传输率只描述磁头已经在目标磁道、连续读写的极限；真实的小文件随机读，有效吞吐率会低得多。这也是磁盘调度和文件系统预读重要的原因。

03

DMA 时间：总线搬运与 CPU 开销分开

每次总线传送 4 B（32 位） 传送次数 = 64 KiB / 4 B = 16384 次 总线周期 = 1 / 100 MHz = 10 ns DMA 搬运时间 = 16384 × 10 ns = 163.84 μs 初始化时间 = 500 × 10 ns = 5 μs 中断处理时间 = 1000 / 2 GHz = 0.5 μs CPU 总开销 = 5 + 0.5 = 5.5 μs

DMA 搬运的 163.84 μs 不等于 CPU 开销：数据由 DMA 控制器在总线上搬，CPU 可以去执行其他程序（但会与 CPU 争用内存总线）。本题中磁盘传输 64 KiB 需要 0.521 ms，而 DMA 只需 0.164 ms，二者可以重叠，实际 I/O 完成时间主要由磁盘的 0.521 ms 决定，而不是把两个时间相加。

数量级检查 磁盘传输 0.521 ms，DMA 0.164 ms，总线不是瓶颈；CPU 开销 5.5 μs，仅占 I/O 时间的约 0.05%。如果算出的 CPU 开销比磁盘时间还大，通常是把“DMA 搬运时间”误当成了 CPU 时间。
04

拆成 16 次小 DMA：初始化开销放大

16 次初始化 = 16 × 5 μs = 80 μs 原来 1 次初始化 = 5 μs 增加 = 80 − 5 = 75 μs 若每次传完都中断： 中断开销 = 16 × 0.5 μs = 8 μs 总 CPU 开销 = 80 + 8 = 88 μs 比原来的 5.5 μs 多出 82.5 μs

所以大块传输通常更划算；但一次 DMA 占用总线太久，会增加其他设备等待的延迟。实际系统会用散射-聚集 DMA（scatter-gather）、多通道 DMA 或更大的传输粒度来平衡。

“DMA 不占 CPU”只成立于“数据搬运不需要 CPU 逐字执行指令”这个意义上。DMA 初始化、中断处理、以及 DMA 与 CPU 争用内存总线，都会消耗 CPU 时间或拉长 CPU 访存延迟。若 CPU 正在跑 Cache 命中率很高的程序，DMA 的影响会小一些；若频繁访存，影响会明显。

平均存取10.69 ms
DMA 搬运163.84 μs
CPU 开销5.5 μs

评分点

  • 转一圈、平均旋转延迟、传输时间各 1 分。
  • 平均存取时间 10.69 ms 与“同磁道只算一次寻道”2 分。
  • 持续传输率 120 MiB/s、有效吞吐 5.85 MiB/s 共 2 分。
  • DMA 163.84 μs、初始化 5 μs、CPU 开销 5.5 μs 共 3 分。
  • 拆分后增加 75 μs、CPU 不参与搬运但参与初始化/中断 2 分。

易错警报

  • 把 7200 r/min 直接当 7200 r/s，旋转延迟小了 60 倍。
  • 把“平均旋转延迟”算成一圈，而不是半圈。
  • 把 DMA 搬运时间加到 CPU 开销里，得出“CPU 忙了 164 μs”。
  • 把磁盘传输时间与 DMA 时间相加，忽略二者可以重叠。
  • 把 64 KiB 当成 64 000 B，导致与 4 KiB 扇区的整除关系出错。

考场变式

若题目问“采用中断方式、每次中断传 4 B，CPU 开销是多少”，要把 16384 次中断 × 每次中断周期数算进去，结果会远大于 DMA；若问“DMA 与 CPU 同时访存，CPU 性能下降多少”，需要看 DMA 占用内存总线的比例（周期挪用率）。记住三种 I/O 方式的区别：程序查询 CPU 全程忙等，中断 CPU 按数据块/字介入，DMA CPU 只在初始化和结束时介入。
